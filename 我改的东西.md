# Everything I have changed and why 

This project was mostly generated by AI and was not actually run and validated on a clean local machine before it was handed over. Because of that, the repo ended up with a lot of setup issues that only show up when someone tries to run it for real: missing local environment values, broken path aliases, route mismatches, and a database that was never initialized. These are not random bugs in the app itself; they are the result of a project being assembled without a proper local dev setup. We had to fix those problems so the app can run consistently and be shared safely.

## Final remark

The main issue was not one big bug; it was a chain of setup problems. The app was missing the correct file paths, the local data layer had not been initialized, and the repo was still tracking local-only files. Once those were fixed, the project could run normally.

A simple rule for a beginner: if the app says `404`, `500`, or “module not found,” check three things first:

1. Are the file paths and aliases correct?
2. Are the local env files and bindings configured?
3. Does the local database exist and contain the required tables?

For admin access specifically, use the setup flow instead of trying to log in before the first admin exists. The correct path is:

- Start the app locally with `npm run dev`
- Visit `http://localhost:3000/setup#key=YOUR_ADMIN_SETUP_TOKEN`
- Enter the matching `ADMIN_EMAIL` plus a valid username and password
- After that, log in normally at `http://localhost:3000/login`
- The admin portal itself is then available at `http://localhost:3000/admin`
Just use this setup for simplicity: 
username: admin 
email: admin@example.invalid
password: adminadmin0 
Code is whatever your code is 

If those are correct, the app is usually much easier to fix.
