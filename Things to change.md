# Things to change

## Why .gitignore matters

Git is for tracking source code, not random generated files or local machine stuff. If we do not tell Git what to ignore, it can start tracking huge folders, temporary files, environment secrets, and build output. That makes commits messy, slows everything down, and can accidentally push things you should not share.

A .gitignore file is a simple list of patterns Git should skip. It does not delete files; it just keeps them out of version control unless you force-add them.

Think of it like this:
- source code files = keep
- node_modules = install locally, do not commit
- dist/build output = generated by the app, do not commit
- .env files = may contain secrets, do not commit
- logs/temp files = not useful to version control

## What we added to .gitignore

We are ignoring the generated and local-only files that should not be pushed:

- node_modules
- .next, .out, build, dist
- .cache, .turbo, .wrangler
- coverage
- *.log, *.tmp, *.swp
- .DS_Store
- .env and local env files
- package-lock.json (because this project uses pnpm)

This keeps the repo clean and prevents accidental pushes of large or sensitive files.
